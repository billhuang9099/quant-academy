# 从零开始：你的第一个可审计量化研究项目

目标是自己运行代码、核对每一笔钱、解释结果并复现实验。这个项目用股票与 ETF 的低频均线策略训练研究流程，不连接券商、不下实盘单，也不会因为跑出正收益就认定策略可交易。

## 1. 安装 Python（只做一次）

从 Python 官方网站 <https://www.python.org/downloads/> 安装 Python 3.10 或更新版本。Windows 安装时勾选 **Add Python to PATH**；Mac 安装后打开“终端”。无需安装 pandas、NumPy 或其他第三方包，本项目只用标准库。

确认安装：Windows 输入 `py --version`，Mac/Linux 输入 `python3 --version`。如果提示找不到命令，重新打开终端，并核对安装位置；不要把下面的终端命令写进 Python 的 `>>>` 提示符中。若已经进入 `>>>`，先输入 `exit()`。

## 2. 建立文件夹与虚拟环境

在桌面创建 `quant-practice` 文件夹，把 `research.py` 下载进去。可再下载 `prices.csv` 和 `test_research.py`；其中 `prices.csv` 是合成练习样本。终端进入这个文件夹（可输入 `cd ` 后把文件夹拖入终端）。

Mac/Linux：

```sh
python3 -m venv .venv
source .venv/bin/activate
python --version
```

Windows 命令提示符（cmd）：

```bat
py -m venv .venv
.venv\Scripts\activate.bat
python --version
```

如果使用 Windows PowerShell 且激活脚本受限，不需要改系统策略，直接把后续 `python` 替换为 `.venv\Scripts\python.exe`。

虚拟环境是这个项目独立的运行目录；它本身不会下载交易软件。以后重新打开终端只需进入文件夹、激活已有环境，不用重新创建。

## 3. 首次运行：单文件即可开始

如果只下载了 `research.py`，运行下面命令生成样本并回测：

```sh
python research.py --generate-sample prices.csv --seed 42 --days 504 --output results
```

如果已经下载或生成了 `prices.csv`，运行：

```sh
python research.py --data prices.csv --fast 10 --slow 40 --cost-bps 10 --slippage-bps 5 --train-fraction 0.7 --initial-cash 100000 --output results
```

`--generate-sample` 拒绝覆盖已有样本。想再生成一次，用另一个文件名，或直接用已有 `--data prices.csv`。每次 `--output results` 会更新该目录下的 3 个结果文件；需要保留对照实验时改成 `--output results-cost30` 等新目录。

参数单位：10 bps = 0.10% 单边手续费，5 bps = 0.05% 单边不利滑点；训练占比 `0.7` 表示前 70% 日期。快均线必须短于慢均线，训练数据必须足够预热。初始现金与价格需使用同一货币。

`--help` 查看所有参数：

```sh
python research.py --help
```

## 4. 看懂 3 个输出文件

| 文件 | 先检查什么 | 应交出的解释 |
| --- | --- | --- |
| `results/metrics.json` | 输入 SHA-256、参数、测试开始日期、策略/基准/训练/测试指标、假设 | 用的是哪份数据、哪些参数、为何能复现 |
| `results/trades.csv` | signalDate、date、side、quantity、price、commission、slippage、cash、shares | 信号发生在哪一天，为何只能下一开盘成交，成交后资金是否足够 |
| `results/equity.csv` | cash + shares × close = equity、grossReturn − cost / 上日权益 = netReturn | 任选一买一卖手工对账，并解释隔夜跳空由谁承担 |

`sharpe: null` 代表收益没有足够波动、比率无定义，不代表风险为零或表现很好。最大回撤为正的小数，例如 `0.2` 是回撤 20%。年化采用 252 个交易期，在短样本上可能显得很夸张。

## 5. 读代码：从能运行到能修改

用任意纯文本编辑器打开 `research.py`，按以下顺序阅读：

1. `read_prices`：CSV 中字符串怎么变成数值；空值为何不能随便填成 0。
2. `validate_prices`：日期、正价格和成交量的检查；格式正确为何仍不保证数据真实。
3. `run_backtest`：先执行昨日信号，再核算今日损益，最后才计算今日收盘信号。
4. `risk_metrics`：复利、样本标准差、最大回撤分别在算什么。
5. `main`：命令行参数如何进入函数，输出如何保存。

初学练习：在 `main` 的报告中加一行输出最后一天的 `cash` 和 `shares`；再运行并用 `equity.csv` 验证。不要先改策略逻辑。下一步把快/慢窗口改成 20/60，只改变一个变量，使用新的结果目录并写下预测，最后才看结果。

## 6. 运行有意义的测试

把 `test_research.py` 放在同一文件夹，然后运行：

```sh
python -m unittest test_research.py -v
```

测试包括跳空手算、未来数据不能改变过去、收盘不能偷跑到同日开盘、现金与费用对账、成本单调、非法数据拒绝，以及单文件命令行输出。测试通过只说明这些已覆盖的行为正确，不说明所有交易风险已处理。

故障实验：复制脚本到实验目录，把执行用的昨日信号错误改成当日收盘信号，观察因果测试失败。复原后测试应再次通过。这是理解“未来函数”比看定义更直接的方法。

## 7. 替换成有许可的真实股票/ETF 数据

输入 CSV 格式如下（这里的两行仅解释列结构，行数不够回测）：

```csv
date,open,close,volume
2024-01-02,10.10,10.20,123400
2024-01-03,10.25,10.15,234500
```

必须满足日期是 `YYYY-MM-DD`、严格递增且不重复，开盘/收盘为正数，成交量为非负整数。代码不会自动排序、插入缺失日或混用多个标的。一份文件只放一个标的、一个币种、一种频率。

下载真实数据前确认供应商授权、市场与用途限制，遵守其许可，不要分享没有再分发权的数据或把 API 密钥写入脚本/仓库。保存来源 URL、下载日、标的代码、时区、复权方法、成交量单位与交易所日历。

开盘和收盘必须采用一致的复权口径，不能使用“原始开盘 + 复权收盘”。本项目没有单独处理分红现金或拆股股数变化，直接用原始价跨分红拆股日可能错算收益。先对照公司行动与供应商定义，在研究记录中明确处理方法。复权价格用于研究并不等于真实下单价格。

不要用今天仍在上市的股票列表假装过去可交易的股票池。对单标的训练，也要解释为什么在研究前选中它；不能因它事后上涨而选择。检查缺失日是休市、停牌还是数据漏采；样本生成器只排周末，不是交易所日历。

完成核对后，以新文件名运行：

```sh
python research.py --data my_licensed_etf.csv --output results-real-first
```

此时报告来源为 `user-supplied`，脚本不能替你证明来源真实。真实样本外观察还需要未被反复调参查看的新时间段。

## 8. 从研究到模拟，再评估实盘准备

先提交一页研究计划：经济假设、标的选择、数据和成本口径、训练/测试分界、预先确定的参数与停止条件。先定规则，后看结果；测试段不是第二个训练段。

同一个策略至少完成：高成本压力测试、窗口邻域对照、不同市场阶段、与同区间含成本基准比较，并解释风险暴露。不要用合成样本的收益来判断赚钱能力。不同参数同用一个测试集后不能再称其完全未见。

在券商官方模拟环境或纸面记录中逐日记录信号、计划单、订单状态、实际成交与资金；处理整手、T+1、涨跌停、交易日历、最小费用、流动性和拒单。无成交也是应记录的结果。计划止损不保证按该价成交，跳空可能使实际损失超预算。

在真实资金前，应能独立核对账本、处理断网/重复下单/拒单、定义个人资金承受能力与暂停规则，并熟悉券商官方订单说明。本脚本没有实盘接口；课程、回测及模拟结果都不能保证实盘盈利或不亏损。
